# ADR-001. Выбор архитектурного стиля

## Статус
Принято

## Контекст
Проект «Business Metrics Analyzer» разрабатывается командой из 3–4 человек. Требуется быстрый MVP с возможностью последующего масштабирования. Ограничения: бюджет (CN-01) и сроки — запуск через 2 месяца (CN-02). Ключевые NFR: отклик дашборда ≤ 3 с (NFR-01), безопасность (NFR-03), развёртывание в Docker.

## Решение
Выбран **слоистый монолит с элементами Clean Architecture**.

Обоснование:
1. Малая команда и сжатые сроки делают микросервисы избыточными.
2. Слоистая архитектура позволяет отделить бизнес-логику (расчёт KPI) от инфраструктуры (БД, API), что упрощает тестирование.
3. Монолит проще развернуть на старте, при этом архитектура допускает выделение сервисов в будущем без переписывания ядра.

## Альтернативы
1. **Микросервисы** – избыточны для MVP, высокая сложность инфраструктуры и координации команды.
2. **Монолит без слоёв** – быстрый старт, но высокая связность и сложность сопровождения.
3. **Serverless** – ограничения по времени выполнения для batch-импорта данных.

## Последствия
+ Быстрая разработка и развёртывание.
+ Чёткое разделение слоёв упрощает тестирование и поддержку.
− Ограниченная горизонтальная масштабируемость.
− Необходимость рефакторинга при выделении сервисов.
