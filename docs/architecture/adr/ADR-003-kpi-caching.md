# ADR-003. Кэширование KPI в Redis

## Статус
Принято

## Контекст
NFR AD-01: время отклика дашборда ≤ 3 с при объёме данных до 1 млн записей.
Тяжёлые агрегаты по продажам не укладываются в SLA при каждом запросе.

## Решение
Предрасчёт KPI по периодам с сохранением в Redis (TTL 5–10 мин)
и инвалидацией при завершении импорта новых данных.

## Альтернативы
1. Только индексы PostgreSQL — недостаточно для сложных агрегатов.
2. Materialized Views — работают, но инвалидация дороже и менее гибкая.
3. Полный pre-aggregation в отдельной таблице — дублирует Redis.

## Последствия
+ Соблюдение SLA ≤ 3 с, снижение нагрузки на БД.
− Eventual consistency дашборда (до TTL). Приемлемо для KPI-отчётности.
