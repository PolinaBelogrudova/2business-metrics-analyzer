# Ответы на контрольные вопросы (Практическое занятие № 2)

**1. Чем отличаются бизнес-требования от функциональных и нефункциональных?**
* **Бизнес-требования** описывают зачем нужен продукт (цели и проблемы бизнеса).
* **Функциональные требования** описывают что система должна делать (конкретные функции).
* **Нефункциональные требования** описывают как система должна работать (качество: производительность, безопасность).

**2. Каким критериям должна соответствовать качественная User Story?**
Критериям INVEST: Independent (независимая), Negotiable (обсуждаемая), Valuable (ценная), Estimable (оцениваемая), Small (небольшая), Testable (проверяемая).

**3. Зачем нужны критерии приёмки и как они связаны с тестированием?**
Критерии приёмки определяют условия, при которых задача считается выполненной. На их основе тестировщики пишут тест-кейсы (в формате Given-When-Then), чтобы проверить работоспособность функции.

**4. Какие элементы включает Use Case-диаграмма?**
Акторы (пользователи/системы), варианты использования (функции системы), связи между ними и границы системы (прямоугольник).

**5. Что такое backlog и как он приоритизируется?**
Backlog — это упорядоченный список всех задач проекта. Приоритизируется с помощью методов MoSCoW (Must have, Should have, Could have, Won't have), оценки в Story Points и матрицы «Ценность/Сложность».

**6. Как связаны User Stories, Use Cases и backlog?**
User Stories описывают требования от лица пользователя. Use Cases визуализируют сценарии взаимодействия с системой. Backlog управляет порядком разработки этих историй (приоритет и спринты).

**7. Какие методы сбора требований вы знаете? В каких ситуациях они применяются?**
Интервью (для детального общения с заказчиком), анкетирование (для сбора данных от многих пользователей), наблюдение (когда пользователь не может объяснить свои действия), анализ документов (изучение старых отчётов), воркшопы (для совместной генерации идей).
